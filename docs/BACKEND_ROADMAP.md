# مزايا تتطلب Backend مستقبلًا

القيود الحالية ناتجة عن بنية GitHub-only الثابتة. هذه المزايا تحتاج خادمًا (أو خدمة مُدارة) عند الحاجة إليها:

| الميزة | لماذا تتطلب خادمًا | نقطة الترقية في الكود |
| --- | --- | --- |
| **مصادقة حقيقية** للمستخدمَين | التحقق من الهوية يجب أن يتم على خادم موثوق | `User.authProviderId`, `services/core.ts#setActor` |
| **مزامنة تلقائية بين الأجهزة** | تتطلب مخزنًا مركزيًا وحل تعارضات | واجهة `Repository<T>` — أضف محوّل Sync بدل `DexieRepository` |
| **مشاركة حقيقية بين المستخدمَين على أجهزة مختلفة** | بيانات مشتركة مركزية مع صلاحيات | نفس ما سبق + تحقق صلاحيات خادمي |
| **استدعاء Gemini مباشرة** | مفتاح API يجب أن يبقى سريًا على الخادم | `GeminiProxyProvider` + `VITE_AI_PROXY_URL` |
| **تنبيهات Push والتطبيق مغلق** | Web Push يتطلب خادمًا يرسل الإشعارات (VAPID) | `notificationService` |
| **تذكيرات بالبريد/الرسائل** | إرسال من خادم مجدول | — |
| **تخزين ملفات كبيرة/فيديو** | سعة تخزين مركزية خاصة (لا تصلح Pages لها) | `deliverableService` (حقل `externalUrl` جاهز) |
| **نسخ احتياطي سحابي تلقائي** | مخزن خارجي مشفّر | `backupService.buildBackup()` |
| **تقارير PDF مولّدة خادميًا** | مكتبات تشكيل عربي على الخادم | `exportService.pdf` |
| **سجل تدقيق غير قابل للتلاعب** | السجل المحلي قابل للتعديل من المستخدم | `logActivity()` |
| **استعادة كلمة المرور دون فقد البيانات** | يتطلب حفظ مفتاح استرداد خارج الجهاز | `keyring.wrapMaster()` (مفتاح استرداد إضافي) |

## مسار ترقية مقترح

1. وسيط خفيف (مثل دالة سحابية) يحتفظ بمفتاح Gemini ويستقبل `{ prompt }` ويعيد `{ text }`.
2. مصادقة عبر مزود هوية (OIDC) وربط `authProviderId`.
3. محوّل مستودع متزامن (مثل CRDT أو مزامنة بالطوابع الزمنية) يطبّق نفس واجهة `Repository<T>`.
4. Web Push بخادم VAPID.

> تنبيه: هذه الخطوات تخرج عن قيد «GitHub-only» الحالي وتتطلب قرارًا صريحًا من المالك.
